# Кабинет учителя и сценарий защиты

Основа — main на 56b9b7b. Зона 1 владеет кабинетом, данными и публичным API. Зона 2 владеет OCR, проверкой, отчётами и артефактами. Зона 3 владеет интерфейсом и репетицией. Чек-лист обновляет маршрут фотопроверки, описанный в прежнем плане. [План фотопроверки](photo-demo-plan.md)

## Маршрут учителя

1. Открывает список работ. Карточка показывает дату, название и класс. В начале сетки — создание, над карточками — добавление класса, сортировка, фильтр и режим удаления с подтверждением.
2. Создаёт работу. Вводит название, прикладывает условие, задаёт критерии, предмет, класс и дату. Из конструкции «№ 1 — 3 балла» интерфейс показывает найденный максимум. Нажатие «Далее» сохраняет работу и открывает её ведомость.
3. Загружает один ZIP или несколько снимков. Для нескольких листов одного ученика использует одинаковое имя и суффиксы __01, __02. Сбор работ доступен пока готовятся эталоны. Сомнительную привязку можно подтвердить в ведомости. [Памятка об именах](photo-filenames.md)
4. Смотрит ведомость. В строке ученик, по заданиям балл и причина, затем сумма, школьная оценка, статус и опубликованный отзыв. Полностью нечитаемая работа и спорный фрагмент имеют разные отметки. Ведомость и отчёт класса выгружаются в Excel.
5. Открывает имя ученика. Смотрит листы и рамки замечаний, выбирает оценку от 2 до 5, редактирует общий отзыв и публикует выбранную ревизию. Кнопки «Предыдущий» и «Следующий» переключают ученика внутри окна. Опубликованный отзыв доступен в Markdown.
6. Переключается в «Отчёт класса». Видит число сдавших, ожидающих и несдавших, статистику заданий и повторяющиеся ошибки с темами и примерами.

Школьную оценку ставит учитель. «Фильтр» в ведомости и аккаунт в шапке предусмотрены как заглушки. Дата на карточке — дата работы, заданная учителем. Сортировка по дате изменения требует данных от кабинета.

## Зона 1. Кабинет и данные

- [x] Классы, список учеников и удаление ученика. Удалённый ученик исчезает из активного списка, его исторические проверки сохраняются.
- [x] Список работ класса, создание по фото или DOCX, название, предмет, дата, требования и максимумы по номерам. Удаление контрольной требует явного подтверждения.
- [x] Импорт ZIP и нескольких фото, одна проверка на комплект, ручная привязка, последняя активная сдача по ревизии, защищённые ссылки на листы.
- [x] Версионные правки оценки и отзыва, публикация и скачивание конкретной ревизии в Markdown.
- [x] Добавить список активных импортов по работе с незакрытыми привязками. Незавершённые импорты можно восстановить в другом браузере через API кабинета. Приёмка — открыть тот же класс в новом браузере и подтвердить оставшуюся привязку.
- [ ] Если нужен фильтр именно по изменению, отдавать время последнего изменения работы отдельно от назначенной даты. Зафиксировать, какие события меняют его. Приёмка — изменение в работе влияет на порядок, а дата в карточке сохраняется.
- [ ] Согласовать повторную загрузку исправленного условия из ведомости. Кабинет уже принимает новую ревизию с тем же идентификатором. Приёмка — старые сдачи остаются у прежней ревизии, интерфейс явно показывает, к какой относится ведомость.

## Зона 2. OCR, оценивание и отчёты

- [x] Фото условия по математике и физике, подготовка эталонов и чтение нескольких листов по порядку.
- [x] Серверные баллы и комментарии по заданиям, различение нечитаемой работы и сомнений по фрагменту, привязки замечаний к странице и к строке.
- [x] Версионная оценка учителя, сводка по опубликованной ревизии, темы для повторения и скачиваемый Markdown.
- [ ] Прогнать реальные фото демонабора. Сверить единицы, дроби, нечитаемые фрагменты и попадание рамок на повёрнутых снимках. Для ненадёжной геометрии показывать замечание и строку, если она определена.
- [x] Сохранять переносы строк и абзацы общего отзыва при выгрузке Markdown. Общий отзыв вводится как обычный текст. Сервис экранирует авторскую разметку и формирует структуру отчёта.
- [x] Оставить ручной частичный балл без отдельной рубрики. Учитель задаёт значение в пределах максимума через API проверки, сервер сохраняет его в новой ревизии и пересчитывает сумму. Разбивка по критериям и основания каждого снятого балла в эту версию не входят.

## Локальный запуск

Кабинету нужна действующая сессия. В dev-режиме Vite использует существующего демо-учителя и подставляет сессию в запросы к кабинету. Если кабинет работает на другом порту или с другой тестовой учёткой, задайте CHECKER_CABINET_URL, CHECKER_TEACHER_EMAIL и CHECKER_TEACHER_PASSWORD в frontend/.env.local. По умолчанию адрес кабинета — http://127.0.0.1:18080.

В корне проекта поднимите стенд по инструкции и создайте демо-учителя. Затем из каталога frontend выполните npm ci и npm run dev. Для проверки сборки выполните npm run build. [Запуск стенда и демо-учитель](../../CONTRIBUTING.md#стенд)

- На изолированном стенде с реальным кабинетом и тестовым движком пройдены создание, импорт DOCX из ZIP, появление результата, ручная оценка, публикация Markdown и сохранение оценки после перезагрузки.

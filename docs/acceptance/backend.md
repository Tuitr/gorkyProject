# Протокол приёмки бэкенда (E6.3)

Совместный результат трёх зон: кабинет (№ 1), проверка `grading` (№ 2), эталоны и шлюз модели (№ 3).
Протокол фиксирует версии, команду и прослеживаемую цепочку одного прогона. Секретов в нём нет.

| Набор данных | `mini.v1`, вариант `e2e1`: `manifest.json` sha256 `7cf503fb…a532`, `bundles/e2e1.zip` sha256 `4af1cfce…7f87`, `assignments/e2e1.docx` sha256 `fdacea06…73da` |

| Стенд | `deploy/compose.yaml`, профиль `full`: `postgres:16`, `redis:7.4-alpine`, `chrislusf/seaweedfs:4.05`, образы `gorky-cabinet:dev` и `gorky-backend:dev` на `python:3.13-slim` и `uv 0.13.4` |

## Воспроизводимая команда

```
docker compose -f deploy/compose.yaml up -d --build --wait
uv run mypy
uv run pytest -rs
```

Сквозной сценарий сам поднимает изолированный проект `gorky-e2e-<id>` с профилем `full` и удаляет его после
прогона (подробности и переменные `E2E_*` — в [CONTRIBUTING](../../CONTRIBUTING.md#сквозной-сценарий-e2e)).
В CI те же стадии выполняет [Backend checks](../../.github/workflows/backend.yml).

## Сценарий

Публичный `/v1` кабинета, шаги E1–E5 из `tests/e2e/testTeacherJourney.py`:

1. Учитель регистрируется и входит, создаёт класс и двух учеников из открытого набора.
2. Публикует вариант `e2e1.docx` и загружает ZIP `e2e1.zip` с двумя работами, подтверждает привязку.
3. Повторно загружает тот же DOCX: кабинет возвращает ту же попытку и ту же проверку.
4. Ждёт результатов: оба ответа верные, у второго ученика одно замечание `sign` на шаге `s2`.
5. Читает отчёт класса: 2 верных из 2, у одного ученика замечание `sign`.
6. Убирает замечание и ставит `reasoning: valid`, повторяет ту же правку (тот же `editId`, тот же ответ).
7. Отчёт показывает новую ревизию без замечания. Учитель публикует обе проверки, перечитывает их по `checkId`
   (`publishedResultRev` равен выбранной ревизии) и скачивает Markdown выбранной ревизии.

## Чего этот результат не доказывает

Сквозной тест идёт на детерминированных ответах шлюза и синтетическом наборе. Он подтверждает, что цепочка
сервисов, контракты, ревизии и выгрузка работают вместе. Он не измеряет точность замечаний (precision/recall)
и экономию времени учителя: для этих метрик нужен отдельный пилот с реальными работами, независимой разметкой
и вызовами настоящей модели.
